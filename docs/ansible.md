# Ansible — Documentation (English)

This document describes how Ansible is used to configure the Kubernetes cluster provisioned by Terraform in this repository.

Summary
- Control node: a dedicated VM created by Terraform named `ansible-01`. Ansible is executed from that machine.
- Main playbook: `ansible/playbook.yml`
- Inventory: generated dynamically from Terraform outputs by the script `scripts/generate_and_copy_ansible.sh`. The default inventory file path is `ansible/inventory.ini`.

Overview
This Ansible setup configures Ubuntu 20.04 VMs (masters and workers) for Kubernetes using containerd + kubeadm + Flannel (CNI). The Ansible control node (ansible-01) is created by Terraform at the same time as the target VMs and receives the private key used to access the cluster nodes.

Prerequisites
- Ansible control node: `ansible-01` (Ubuntu) with the private SSH key generated by Terraform and provisioned during cloud-init.
- Target nodes: Ubuntu 20.04
- Ansible installed on the control node (>= 2.9 recommended; 2.10+ preferred)
- Python 3 installed on target nodes (inventory sets `ansible_python_interpreter=/usr/bin/python3`)
- `kubectl` will be used on the master node (the playbook copies `admin.conf` into `/home/ubuntu/.kube/config`)

Inventory generation (from Terraform outputs)
- Inventory is generated dynamically by `scripts/generate_and_copy_ansible.sh` which reads Terraform outputs (IP addresses, names) and creates `ansible/inventory.ini`.
- The docs should include a link or reference to `scripts/generate_and_copy_ansible.sh`. Example usage:
  1. Run `terraform apply` to create VMs.
  2. Run `./scripts/generate_and_copy_ansible.sh` from your local machine or from a helper script to produce `ansible/inventory.ini` and copy files to `ansible-01` if needed.
- The inventory generated by the script should match the format shown in the Examples section below.

How to run (examples)
From the Ansible control node `ansible-01` (or run the below with SSH into `ansible-01`), run:

ANSIBLE_HOST_KEY_CHECKING=False ansible-playbook -i ansible/inventory.ini ansible/playbook.yml --user ubuntu --private-key ~/.ssh/id_ansible

Notes:
- `ANSIBLE_HOST_KEY_CHECKING=False` disables the SSH strict host key checking for first-time connections. Alternatively, manage known_hosts.
- The inventory included in this project sets `ansible_ssh_private_key_file=/home/ubuntu/.ssh/id_ansible` and `ansible_user=ubuntu`. When executing locally on `ansible-01`, ensure the private key path matches.
- If you use Ansible from a different machine, adjust `--private-key` to point to the private key used to access cluster nodes.

Playbook: purpose & flow
High-level flow implemented by `ansible/playbook.yml`:
1. Preparation common to all nodes (master + workers)
   - Disable swap (runtime + /etc/fstab)
   - Load kernel modules: `overlay`, `br_netfilter`
   - Persist kernel modules and sysctl settings required by Kubernetes
   - Install base packages and repositories
   - Install and configure containerd (ensure `SystemdCgroup = true`)
   - Install `kubelet`, `kubeadm`, `kubectl` and mark them on hold
2. Initialize the control-plane (master)
   - Run `kubeadm init` on the master with `--pod-network-cidr`
   - Create `/home/ubuntu/.kube/config` so `kubectl` can be used as ubuntu
   - Capture the `kubeadm join` command so workers can join
   - Deploy the Flannel CNI manifest (download + `kubectl apply`)
3. Join worker nodes
   - Execute the previously captured `kubeadm join` command on each worker (guarded to avoid re-running if node already configured)

Key implementation notes from the provided playbook:
- The playbook uses `become: true` at the plays level to run privileged tasks.
- The playbook explicitly avoids acting on `ansible-01` using `ansible.builtin.meta: end_host`.
- The master init task uses `creates: /etc/kubernetes/admin.conf` to make `kubeadm init` idempotent.
- Worker join uses `creates: /etc/kubernetes/kubelet.conf` to avoid repeated joins.
- Flannel manifest application is run as the `ubuntu` user with `KUBECONFIG` pointing to `/home/ubuntu/.kube/config`.

Variables, secrets & Vault
- The playbook defines inline variables for Kubernetes in the plays (e.g. `kubernetes_version`, `kubeadm_kubernetes_version`, `pod_network_cidr`). You can move these variables into `group_vars` or `host_vars` for easier customization.
- Inventory `all:vars` contains:
  - `ansible_python_interpreter=/usr/bin/python3`
  - `ansible_ssh_private_key_file=/home/ubuntu/.ssh/id_ansible`
  - `ansible_user=ubuntu`
- Secrets handling:
  - Private SSH key: generated by Terraform and placed on `ansible-01` (`/home/ubuntu/.ssh/id_ansible`). Do NOT commit private keys to the repository.
  - If you need encrypted secrets (e.g. tokens, certs), use Ansible Vault:
    - Create: `ansible-vault create group_vars/all/vault.yml`
    - Edit: `ansible-vault edit group_vars/all/vault.yml`
    - Run playbook with: `ansible-playbook --ask-vault-pass ...` or `--vault-password-file /path/to/vault_password_file`
- Document any pipeline/CI usage of Vault if you plan automated runs (e.g. use secrets manager or GitHub Actions secrets).

Idempotence & re-runs
- The playbook is mostly idempotent:
  - `kubeadm init` uses `creates: /etc/kubernetes/admin.conf` — so it will not re-run once finished.
  - `kubeadm join` uses `creates: /etc/kubernetes/kubelet.conf`.
- Re-running the playbook is safe for configuration tasks. If you must re-run cluster bootstrap steps, be aware:
  - To completely reset a node (manual operation): `sudo kubeadm reset` and clean `/etc/kubernetes/*`, then re-run join/init.
  - If a join failed, inspect the master `kubeadm token` or re-generate with `kubeadm token create --print-join-command` (the playbook already registers and shares a join command).
- The playbook marks packages on hold (`apt-mark hold`) for kube* packages to avoid unintended upgrades—manage upgrades carefully.

Verification & post-install checks
After a successful run, from the master node (or from a machine with admin kubeconfig):
- Verify nodes: kubectl get nodes -o wide
- Verify system services: sudo systemctl status kubelet
- Verify pods & CNI: kubectl get pods -A
- Confirm Flannel pods: kubectl -n kube-system get pods -l app=flannel

Troubleshooting — common issues
- SSH issues: ensure the public key provisioned by Terraform/cloud-init is present on each VM and the private key is on the Ansible control node at the path used in inventory.
- cloud-init timing: some tasks may fail if the VM is not fully initialized. Use the provided scripts (e.g. `scripts/wait_for_ssh.sh`) to ensure SSH is reachable before running Ansible.
- apt locks / concurrent package managers: retries or waiting may be necessary on first-boot when cloud-init is still installing packages.
- Swap: must be disabled for kubelet. Playbook disables swap and comments it out in `/etc/fstab`.
- kubeadm/kubelet version compatibility: ensure chosen Kubernetes version is supported on Ubuntu 20.04. Check the official kubeadm docs for version skew policies.
- Container runtime config: ensure `SystemdCgroup = true` is set in containerd config (the playbook enforces this).
- Repeated join errors: check that the join command from the master is valid and tokens have not expired. Use `kubeadm token list` and `kubeadm token create` if needed.

Examples & snippets
Below are useful examples taken from the current setup.

Inventory example (`ansible/inventory.ini`):
```ini
[all]
ansible-01    ansible_host=192.168.1.10
k8s-master-01 ansible_host=192.168.1.11
k8s-worker-01 ansible_host=192.168.1.12
k8s-worker-02 ansible_host=192.168.1.13
k8s-worker-03 ansible_host=192.168.1.14

[all:vars]
ansible_python_interpreter=/usr/bin/python3
ansible_ssh_private_key_file=/home/ubuntu/.ssh/id_ansible
ansible_user=ubuntu
```

Recommended `ansible.cfg` snippet (optional; place in repo root or `/etc/ansible/ansible.cfg` on control node):
```ini
[defaults]
inventory = ansible/inventory.ini
host_key_checking = False
remote_user = ubuntu
timeout = 30
forks = 20
pipelining = True

[ssh_connection]
scp_if_ssh = True
```

Full playbook (primary `ansible/playbook.yml`)
Below is the full playbook content as provided (use this file in the repo under `ansible/playbook.yml`):

```yaml
---
# 1. Préparation de tous les noeuds (master + workers)
- name: Préparation des noeuds Kubernetes
  hosts: all
  become: true
  vars:
    kubernetes_version: "1.29"
    kubeadm_kubernetes_version: "1.29.0-*"
    pod_network_cidr: "10.244.0.0/16"
  tasks:
    - name: Ne rien faire sur la machine ansible-01
      ansible.builtin.meta: end_host
      when: inventory_hostname == "ansible-01"

    - name: Désactiver le swap (runtime)
      ansible.builtin.command: swapoff -a
      when: ansible_swaptotal_mb | int > 0

    - name: Commenter le swap dans /etc/fstab
      ansible.builtin.replace:
        path: /etc/fstab
        regexp: '^([^#].*\s+swap\s+.*)$'
        replace: '# \1'

    - name: Charger les modules noyau nécessaires
      ansible.builtin.modprobe:
        name: "{{ item }}"
        state: present
      loop:
        - overlay
        - br_netfilter

    - name: Assurer la persistance des modules
      ansible.builtin.copy:
        dest: /etc/modules-load.d/k8s.conf
        content: |
          overlay
          br_netfilter
        mode: '0644'

    - name: Paramètres sysctl pour Kubernetes
      ansible.builtin.copy:
        dest: /etc/sysctl.d/k8s.conf
        content: |
          net.bridge.bridge-nf-call-iptables  = 1
          net.bridge.bridge-nf-call-ip6tables = 1
          net.ipv4.ip_forward = 1
        mode: '0644'

    - name: Recharger sysctl
      ansible.builtin.command: sysctl --system

    - name: Installer paquets de base
      ansible.builtin.apt:
        name:
          - apt-transport-https
          - ca-certificates
          - curl
          - gnupg
          - lsb-release
        state: present
        update_cache: true

    # ------- Installation containerd -------
    - name: Ajouter clé GPG Docker
      ansible.builtin.apt_key:
        url: https://download.docker.com/linux/ubuntu/gpg
        state: present

    - name: Ajouter dépôt Docker
      ansible.builtin.apt_repository:
        repo: "deb [arch=amd64] https://download.docker.com/linux/ubuntu {{ ansible_distribution_release }} stable"
        state: present
        filename: docker

    - name: Installer containerd
      ansible.builtin.apt:
        name: containerd.io
        state: present
        update_cache: true

    - name: Sauvegarder une éventuelle ancienne config containerd
      ansible.builtin.copy:
        src: /etc/containerd/config.toml
        dest: /etc/containerd/config.toml.bak
        remote_src: true
      ignore_errors: true

    - name: Générer une config par défaut de containerd (avec CRI activé)
      ansible.builtin.command: >
        bash -c "containerd config default > /etc/containerd/config.toml"

    - name: Forcer SystemdCgroup à true dans la config containerd
      ansible.builtin.replace:
        path: /etc/containerd/config.toml
        regexp: 'SystemdCgroup = false'
        replace: 'SystemdCgroup = true'

    - name: S'assurer que le plugin CRI n'est pas désactivé
      ansible.builtin.replace:
        path: /etc/containerd/config.toml
        regexp: '^disabled_plugins *=.*'
        replace: 'disabled_plugins = []'
      ignore_errors: true

    - name: Redémarrer containerd
      ansible.builtin.systemd:
        name: containerd
        state: restarted
        enabled: true

    # ------- Installation kubeadm/kubelet/kubectl -------
    - name: Ajouter clé GPG du dépôt Kubernetes
      ansible.builtin.apt_key:
        url: https://pkgs.k8s.io/core:/stable:/v{{ kubernetes_version }}/deb/Release.key
        state: present

    - name: Ajouter dépôt Kubernetes
      ansible.builtin.apt_repository:
        repo: "deb https://pkgs.k8s.io/core:/stable:/v{{ kubernetes_version }}/deb/ /"
        state: present
        filename: kubernetes

    - name: Installer kubelet, kubeadm, kubectl
      ansible.builtin.apt:
        name:
          - kubelet={{ kubeadm_kubernetes_version }}
          - kubeadm={{ kubeadm_kubernetes_version }}
          - kubectl={{ kubeadm_kubernetes_version }}
        state: present
        update_cache: true

    - name: Marquer les paquets Kubernetes en hold
      ansible.builtin.command: >
        apt-mark hold kubelet kubeadm kubectl


# 2. Initialisation du master
- name: Initialiser le master Kubernetes
  hosts: k8s-master-01
  become: true
  vars:
    pod_network_cidr: "10.244.0.0/16"
    flannel_manifest_url: "https://raw.githubusercontent.com/flannel-io/flannel/master/Documentation/kube-flannel.yml"
  tasks:
    - name: Initialiser le control-plane avec kubeadm
      ansible.builtin.command: >
        kubeadm init
        --pod-network-cidr={{ pod_network_cidr }}
        --apiserver-advertise-address={{ ansible_default_ipv4.address }}
      args:
        creates: /etc/kubernetes/admin.conf
      register: kubeadm_init

    - name: Créer le dossier .kube pour ubuntu
      ansible.builtin.file:
        path: /home/ubuntu/.kube
        state: directory
        owner: ubuntu
        group: ubuntu
        mode: '0700'

    - name: Copier le fichier admin.conf
      ansible.builtin.copy:
        src: /etc/kubernetes/admin.conf
        dest: /home/ubuntu/.kube/config
        owner: ubuntu
        group: ubuntu
        mode: '0600'
        remote_src: true

    - name: Récupérer la commande join
      ansible.builtin.command: kubeadm token create --print-join-command
      register: kubeadm_join_cmd

    - name: Enregistrer la commande join en variable de fait
      ansible.builtin.set_fact:
        join_command: "{{ kubeadm_join_cmd.stdout }}"

    # ------- Installation du CNI Flannel -------
    - name: Télécharger le manifest Flannel
      ansible.builtin.get_url:
        url: "{{ flannel_manifest_url }}"
        dest: /tmp/kube-flannel.yml
        mode: '0644'

    - name: Appliquer le CNI Flannel
      become: true
      become_user: ubuntu
      ansible.builtin.command: >
        kubectl apply -f /tmp/kube-flannel.yml
      environment:
        KUBECONFIG: /home/ubuntu/.kube/config


# 3. Join des workers
- name: Ajouter les workers au cluster
  hosts: all
  become: true
  vars:
    master_host: "k8s-master-01"
  tasks:
    - name: Ne rien faire sur ansible-01 et sur le master
      ansible.builtin.meta: end_host
      when: inventory_hostname in ["ansible-01", master_host]

    - name: Exécuter kubeadm join
      ansible.builtin.command: "{{ hostvars[master_host].join_command }} --v=5"
      args:
        creates: /etc/kubernetes/kubelet.conf
```
